## 3.4.1 Pourquoi IPv6 ?

L'espace IPv4 (≈ 4,3 milliards d'adresses) est épuisé. Le CIDR, le NAT et les adresses privées ont seulement **retardé** l'échéance ; surtout, le NAT casse la communication de bout en bout. **IPv6** (RFC 8200, adressage RFC 4291) code les adresses sur **128 bits**, soit ≈ 3,4 × 10³⁸ adresses.

Particularités :

- Une adresse est attribuée à une **interface**, et une interface a **plusieurs** adresses (lien-local, globale...).
- **Pas de NAT** : chaque équipement peut avoir une adresse globale.
- **Pas de diffusion** (broadcast) : on utilise le multicast. **ICMPv6** remplace ICMP ; **NDP** remplace ARP ; **MLD** remplace IGMP.
- L'en-tête a une taille **fixe de 40 octets** : Version, Traffic Class, Flow Label, Payload Length, **Next Header**, **Hop Limit** (équivalent du TTL), adresses source et destination (128 bits chacune). Plus de somme de contrôle.

## 3.4.2 Écrire une adresse IPv6

Une adresse = **8 groupes de 16 bits** en hexadécimal, séparés par `:`.

`2003:0000:0000:00fc:0000:0000:0000:0ba1`

Deux règles de compression :

1. Dans un groupe, on peut **supprimer les zéros de tête** : `00fc` devient `fc`, `0ba1` devient `ba1`.
2. **Une seule fois** dans l'adresse, une suite de groupes nuls consécutifs peut être remplacée par `::`.

L'adresse ci-dessus s'écrit donc `2003:0:0:fc::ba1` (on a compressé la **plus longue** suite de zéros) ou `2003::fc:0:0:0:ba1`.

:::attention Le `::` une seule fois
`fe80::4cd:ffa1::1` est **invalide** : deux `::` rendent l'adresse ambiguë. Autre piège : ne jamais supprimer un zéro **de queue** (`2001:db8:10:...` : `10` n'est pas `1`).
:::

### Le préfixe

Comme en CIDR, on écrit `/n` : `2001:db8:acad:1::/64`. Les sous-réseaux LAN sont presque toujours des **/64** (64 bits de réseau, 64 bits d'identifiant d'interface).

## 3.4.3 Types d'adresses

| Type | Préfixe | Usage |
|---|---|---|
| **Global unicast (GUA)** | `2000::/3` | Routable sur Internet |
| **Lien-local (LLA)** | `fe80::/10` | Valable sur le lien seul, non routable, toujours présente |
| **Unique locale (ULA)** | `fc00::/7` (en pratique `fd00::/8`) | Équivalent des adresses privées |
| **Multicast** | `ff00::/8` | Un émetteur, plusieurs destinataires |
| **Loopback** | `::1/128` | La machine elle-même |
| **Non spécifiée** | `::/128` | « aucune adresse » |
| **Documentation** | `2001:db8::/32` | Exemples |
| **6to4** | `2002::/16` | Tunnel IPv6 sur IPv4 |

Trois modes d'envoi : **unicast** (un vers un), **multicast** (un vers plusieurs), **anycast** (un vers le plus proche, des mêmes adresses sont portées par plusieurs équipements).

### Multicast bien connus

| Adresse | Cible |
|---|---|
| `ff02::1` | Tous les nœuds du lien |
| `ff02::2` | Tous les routeurs du lien |
| `ff02::5` / `ff02::6` | Routeurs OSPFv3 / DR |
| `ff02::1:2` | Serveurs et relais DHCPv6 |

Le 4e chiffre indique la **portée** : `ff01` interface, `ff02` lien, `ff05` site, `ff08` organisation, `ff0e` globale.

## 3.4.4 Comment une interface obtient son adresse

- **Manuelle** : `2001:db8:acad:1::1/64`.
- **EUI-64** : le suffixe est construit à partir de l'**adresse MAC** (on insère `fffe` au milieu et on inverse le 7e bit) ; on peut aussi utiliser des identifiants aléatoires (confidentialité).
- **SLAAC** (*Stateless Address Autoconfiguration*, RFC 4862) : le routeur annonce le **préfixe** dans un **Router Advertisement**, le poste fabrique lui-même son suffixe.
- **DHCPv6** : avec état (*stateful*, attribue l'adresse) ou sans état (ne donne que DNS, domaine).

### Le protocole NDP (Neighbor Discovery)

NDP utilise ICMPv6 :

| Message | Rôle |
|---|---|
| **RS** (Router Solicitation) | Un hôte demande « y a-t-il un routeur ? » |
| **RA** (Router Advertisement) | Le routeur annonce préfixe, passerelle, options |
| **NS** (Neighbor Solicitation) | Équivalent de la requête ARP |
| **NA** (Neighbor Advertisement) | Équivalent de la réponse ARP |
| **Redirect** | Indique un meilleur routeur |

NS/NA servent aussi à la **détection de doublons** (DAD) avant d'utiliser une adresse.

## 3.4.5 Configurer IPv6

### Cisco

```text
R1(config)# ipv6 unicast-routing                ! active le routage IPv6 (indispensable)
R1(config)# interface g0/0
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64
R1(config-if)# ipv6 enable
R1(config-if)# no shutdown
R1(config)# ipv6 route 2001:db8:acad:3::/64 2001:db8:acad:12::2
R1(config)# ipv6 route ::/0 2001:db8:acad:12::2        ! route par défaut
```

### Linux

```bash
ip -6 addr add 2001:db8:acad:1::10/64 dev eth0
ip -6 route add 2001:db8:acad:3::/64 via 2001:db8:acad:1::1
ip -6 route add default via 2001:db8:acad:1::1
ip -6 route show
ping -6 2001:db8:acad:1::1
```

Pour un voisin de lien-local, il faut préciser l'interface : `ping6 fe80::1%eth0`.

## 3.4.6 Coexistence avec IPv4

| Mécanisme | Principe |
|---|---|
| **Double pile** (*dual stack*) | IPv4 et IPv6 en même temps sur chaque équipement |
| **Tunnels** (6to4, 6rd, ISATAP, Teredo) | IPv6 encapsulé dans IPv4 |
| **NAT64 / DNS64** | Traduction entre un réseau IPv6 seul et IPv4 |

:::retenir À retenir
128 bits, 8 groupes de 16, `::` une seule fois. `fe80::/10` lien-local, `2000::/3` global, `fc00::/7` ULA, `ff00::/8` multicast. Pas de NAT, pas de broadcast, ARP remplacé par NDP. `ipv6 unicast-routing` pour router.
:::

:::examen Ce qui tombe à l'examen
Compresser ou décompresser des adresses, reconnaître le type par le préfixe, écrire une route statique IPv6, citer les messages NDP. L'énoncé 3 du TD du cours demande aussi les tables de R1 et R2 en IPv4 **et** IPv6.
:::

## 3.4.7 Exercices corrigés

**Exercice 1.** Compressez au maximum : `2001:0db8:0000:0000:0008:0800:200C:417a`.

<details>
<summary>Voir le corrigé</summary>

`2001:db8::8:800:200c:417a`

</details>

**Exercice 2.** Compressez : `ff01:0000:0000:0000:0000:0000:0000:0101` et `0000:0000:0000:0000:0000:0000:0000:0001` et `0000:0000:0000:0000:0000:0000:0000:0000`.

<details>
<summary>Voir le corrigé</summary>

`ff01::101` ; `::1` ; `::`.

</details>

**Exercice 3.** Écrivez sans compression : `fe80::1` et `2001:0:bebe::face:c001`.

<details>
<summary>Voir le corrigé</summary>

`fe80:0000:0000:0000:0000:0000:0000:0001` ; `2001:0000:bebe:0000:0000:0000:face:c001`.

</details>

**Exercice 4.** Pourquoi `fe80::4cd:ffa1::1` est-elle invalide ?

<details>
<summary>Voir le corrigé</summary>

Elle contient **deux `::`** : on ne peut pas savoir combien de groupes de zéros chacun remplace.

</details>

**Exercice 5.** Identifiez le type : `fe80::a00:27ff:fe4e:66a1`, `2a00:1450::1`, `fd12:3456::1`, `ff02::2`, `::1`.

<details>
<summary>Voir le corrigé</summary>

Lien-local ; global unicast (2000::/3) ; unique locale ; multicast « tous les routeurs du lien » ; loopback.

</details>

**Exercice 6.** Écrivez la route statique IPv6 vers `2001:db8:3::/64` via `2001:db8:12::2`, et la route par défaut.

<details>
<summary>Voir le corrigé</summary>

```text
ipv6 route 2001:db8:3::/64 2001:db8:12::2
ipv6 route ::/0 2001:db8:12::2
```

</details>

**Exercice 7.** Quelle commande indispensable sur un routeur Cisco pour qu'il route l'IPv6 ?

<details>
<summary>Voir le corrigé</summary>

`ipv6 unicast-routing` (en configuration globale).

</details>

**Exercice 8.** Quel mécanisme remplace ARP en IPv6 et quels messages utilise-t-il ?

<details>
<summary>Voir le corrigé</summary>

**NDP** (ICMPv6) : NS (demande de voisin) et NA (annonce de voisin) ; RS/RA pour la découverte des routeurs.

</details>
